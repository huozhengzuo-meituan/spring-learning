OAuth2、OIDC 与 JWT 资源服务器

画清身份提供方、客户端和API的职责，并识别JWT验证缺口。

约 35 分钟先修：23Java 21 · Boot 4.1
从你的前端经验出发

前端拿到一个token不代表可以自己判断用户可信；API必须独立验证令牌并执行资源权限规则。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：独立 jshell 实验；OAuth2资源服务器接入设计。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

先分清协议、角色与格式

OAuth2关注授权，OIDC在其上增加身份层，JWT是一种可承载声明的令牌格式。三者不是同义词。客户端让用户到身份提供方登录并获得授权，资源服务器接收访问令牌并保护API；ID Token面向客户端表达登录身份，不应直接当作所有API的访问凭据。

JWT的header和payload通常只是Base64URL编码，任何持有者都能读取，不能在里面放密码或其他需要保密的内容。签名提供完整性和发行者信任判断，不等于加密。把JWT拆成三段并解析出用户名，只证明读到了文本，远没有证明令牌真实有效。

原始资料：Spring Security JWT Resource Server。

资源服务器验证哪些东西

Spring Security的资源服务器支持验证签名、有效期和发行者等条件，并把声明映射到权限。配置issuer-uri能从受信任发行者发现密钥；audience仍应按你的API明确校验，避免接受签给其他资源的令牌。还需考虑允许算法、密钥轮换、时钟偏差和失败时拒绝访问，不能接受令牌header自称的任意算法。

下列是独立扩展配置草案，本项目默认Basic模式没有身份提供方，不会凭这段配置自动获得登录系统。Boot4可使用spring-boot-starter-security-oauth2-resource-server及对应配置。真正接入前先确定发行者、API audience、scope命名和前端授权流程，再添加明确测试。

# 独立OAuth2资源服务器配置草案，示例域名不能直接运行
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://idp.example.test/realms/learning
          audiences: learning-api

# 请求方式：令牌由受信任授权服务器颁发
# Authorization: Bearer <access-token>

原始资料：OpenID Connect Core。

前端流程与服务端授权各守边界

浏览器公共客户端通常使用Authorization Code并结合PKCE；不能把长期client secret打包进前端，因为用户可以读取所有前端资源。重定向URI应精确登记，使用state与OIDC nonce等机制按所选库和协议要求保护流程。令牌如何保管需结合XSS、CSRF与后端代理架构决定，不存在对所有产品都正确的一句“放localStorage”。

一个有效JWT也不代表可以访问任何taskId。scope、角色和资源所有权仍需服务端授权。纯Bearer API若确实只接受显式Authorization头、完全不依赖浏览器自动凭据，才可在明确边界内评估CSRF配置；不能把该结论套到当前Basic或Cookie接口。注销、吊销、短期令牌和密钥失效还需生命周期设计。

原始资料：OAuth 2.0 Security Best Current Practice。

用验证矩阵定义接入完成

接入不能只测一个正常token。至少要验证缺失、过期、错误发行者、错误audience、篡改签名、scope不足和跨用户资源访问。前四类通常应拒绝认证，scope不足应拒绝授权；具体响应按合同稳定处理。记录这张矩阵能让你在身份平台变更、密钥轮换或后端扩容时重复验证。

本课的基础练习是可离线执行的令牌解析与威胁判断；真实IdP接入为挑战任务，需要你提供或搭建受控身份服务。课程不会假装示例域名已经可用，也不会鼓励自己手写密码认证、签名算法或OAuth完整流程。优先使用经过维护的标准实现，把精力放到正确配置和业务权限。

jshell
// 仅演示编码可读性，绝不把它当签名验证
var payload = "{\"sub\":\"learner\",\"aud\":\"learning-api\"}";
var encoded = java.util.Base64.getUrlEncoder().withoutPadding().encodeToString(payload.getBytes(java.nio.charset.StandardCharsets.UTF_8));
System.out.println(new String(java.util.Base64.getUrlDecoder().decode(encoded),
    java.nio.charset.StandardCharsets.UTF_8));
