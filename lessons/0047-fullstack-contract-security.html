全栈联调：OpenAPI、BFF 与安全契约

把前端表单到后端事务的契约连起来，并区分CORS、CSRF与授权。

约 35 分钟先修：Spring Security与HTTP / 第36课：schema演进Java 21 · Boot 4.1
从你的前端经验出发

这是把你已有的前端能力与后端连接的一课：接口类型、错误反馈、身份、并发冲突都要形成一条用户流程。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：examples/task-service；浏览器同源联调增量。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

契约要覆盖失败与并发

OpenAPI描述路径、方法、参数、schema、响应与安全方案；类型生成能减少拼写错误，但不能代替运行时校验和服务端授权。任务状态更新必须包含version，两个浏览器同时编辑时，一个更新成功，另一个收到明确冲突并提示重新加载。错误契约需包含稳定错误码、可理解信息和请求标识，而不是把堆栈返回浏览器。Java long可能超出JavaScript安全整数范围，标识符用字符串可避免精度问题；时间使用明确时区。

浏览器安全不是一个开关

CORS决定哪些来源可在浏览器中读取跨域响应，不是身份认证或服务端防火墙。CSRF防止浏览器自动附带身份的跨站写请求；cookie或浏览器管理的HTTP Basic等情况需要考虑。XSS是脚本执行风险，又是另一层问题。当前课堂项目的Basic用户仅服务本地学习，保留CSRF；真实生产应采用合适身份提供方、会话或OAuth2/OIDC方案。不要为解决联调403直接关闭所有安全配置或把允许来源设成带凭据的通配符。

把 CSRF 获取与写请求连起来

在当前项目的同源、已完成本地认证的浏览器环境中，先获取/api/csrf，再使用响应给出的headerName和token提交。以下演示状态更新（目标任务当前须为IN_PROGRESS），taskId与version应取实际列表详情，不能写死他人资源ID。CSRF令牌不代替权限校验；reader即便有合法CSRF令牌也不能执行writer操作。前端收到409等冲突应保留用户输入并展示差异，不应该自动无上限重试。

const csrf = await fetch("/api/csrf", { credentials: "same-origin" }).then(r => r.json());
const response = await fetch(`/api/tasks/${taskId}/status`, {
  method: "PATCH",
  credentials: "same-origin",
  headers: { "Content-Type": "application/json", [csrf.headerName]: csrf.token },
  body: JSON.stringify({ status: "DONE", version })
});
if (!response.ok) {
  // 根据实际错误契约处理401/403/409；不要把失败当成功更新UI。
  console.error("update failed", response.status);
}

BFF 聚合也需要边界

BFF为特定前端聚合后端数据、管理会话或减少往返，但不应复制核心业务规则或绕过资源授权。用户ID应来自服务端验证的身份，不信任请求体自报身份。前后端联调用例至少包含未登录、权限不足、缺少CSRF、非法字段、版本冲突、服务器超时与成功路径。生成客户端后再与真实API执行契约检查；mock只是开发辅助，不能证明鉴权与事务实际成立。完成时应从页面操作追到真实数据库结果与eventId。

一手阅读：OpenAPI 3.1.1；Spring Security CORS；Spring Security CSRF。把你的实验记录和取舍理由发给学习助手，可以继续追问并获得反馈。

注意示例状态机只允许TODO到IN_PROGRESS再到DONE；如果从TODO直接提交DONE，会得到合法的业务冲突，而非安全配置错误。联调时先确认当前状态，再选择允许的下一状态。把浏览器网络错误、HTTP权限拒绝和业务冲突分开呈现，才能定位真正责任层。

正确答案：请求通过防伪项。CSRF验证与身份授权、业务版本冲突是独立检查；通过一项不能跳过其他项。

把知识变成操作

完成一次双页面并发编辑联调。

  1. 以本地writer登录，获取CSRF与同一任务当前version。
  2. 两个页面都使用旧version更新；记录成功和冲突反馈。
  3. 改为reader身份提交相同请求，验证权限拒绝。
  4. 移除CSRF令牌再提交，说明与CORS失败如何区分。
验收信号

更新与冲突反馈明确；reader不能越权；缺少CSRF得到拒绝；不会靠关闭安全绕过问题。

做完再看：参考答案与排错线索

前端保留失败输入并允许重新获取最新版本；后端分别校验身份、权限、CSRF与version。自动类型生成只解决契约的一部分。
