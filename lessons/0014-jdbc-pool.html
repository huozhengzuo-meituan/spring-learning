JDBC 参数绑定与连接池

写安全的参数化SQL，并解释连接池耗尽时请求为什么等待。

约 30 分钟先修：13Java 21 · Boot 4.1
从你的前端经验出发

数据库调用像访问远程API：有连接成本、资源上限和失败模式；它不是零成本的本地数组操作。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：独立 PostgreSQL / psql 实验；examples/task-service。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

连接、事务与SQL的不同职责

JDBC是Java访问关系数据库的基础接口，驱动实现具体协议，DataSource提供连接，连接池复用有限数量的物理连接。Spring的JdbcTemplate或JdbcClient处理常见资源管理和异常转换，让你集中写SQL与映射。连接用完要归还，归还到池通常不等于真的断开数据库TCP连接。

连接池大不一定吞吐高。数据库CPU、锁和磁盘都有限；大量并发SQL可能彼此争抢而更慢。长事务或慢查询长期占用连接，会让后续请求等待；应用线程变多也不会凭空增加数据库处理能力。评估池容量时同时观察等待时间、活跃连接、数据库负载和请求超时。

原始资料：Spring JDBC Core / JdbcClient。

绑定的是值，不能绑定SQL语法

把用户输入用字符串拼进SQL可能改变语句结构。参数绑定将数据交给驱动处理，标题中的引号仍作为内容。动态表名、排序列和ASC/DESC属于语法，不能指望一个问号参数安全替换它们；应从固定白名单选择经过验证的SQL片段。校验输入长度和参数化不是二选一，二者解决不同问题。

下面是针对教学lab_tasks表的JdbcClient方法示意，需在带JDBC依赖的类中注入JdbcClient，不能直接粘到纯jshell运行。optional表达至多一行可能不存在；single要求恰好一行。更新后的影响行数必须检查，尤其是条件更新，零行可能意味着不存在或并发版本已变化。

record TaskRow(long id, String title) {}

// jdbc 是通过构造器注入的 JdbcClient
var task = jdbc.sql("select id,title from lab_tasks where id=:id")
    .param("id", requestedId)
    .query(TaskRow.class)
    .optional();

int updated = jdbc.sql("update lab_tasks set title=:title where id=:id")
    .param("title", userInput) // 永远不拼接用户标题
    .param("id", requestedId)
    .update();

用独立SQL理解参数边界

执行 docker compose exec postgres psql -U learning -d learning 进入学习库后，psql的PREPARE/EXECUTE能够在没有Java代码的情况下展示参数值与SQL结构的区别。该机制不等于JDBC驱动全部实现细节，却能帮助你形成正确心智模型。下面恶意形状的文本只作为字符串返回，不会额外执行删除命令。实验不包含真实敏感表。

常见陷阱是查询循环中为每条记录再执行一次SQL，引起N+1；另一个是把HTTP远程调用放进数据库事务，连接一直被占用。先尽量缩短数据库资源持有时间，再讨论连接池大小。报告性能时给出测量，不用“用了连接池所以一定快”代替证据。

PREPARE echo_title(text) AS SELECT $1 AS title;
EXECUTE echo_title('x''; DROP TABLE imaginary; --');
DEALLOCATE echo_title;

连接超时、查询超时与事务超时是不同预算。连接超时可能花在等待池中空闲连接，查询超时约束SQL执行，事务超时覆盖事务工作。给所有值写同一个数字不一定满足请求总预算，应把最外层请求期限和内部每次尝试的剩余时间一起考虑。
