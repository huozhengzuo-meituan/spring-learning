用 record 和 Optional 表达边界

在 Java 21 中写清数据、不存在与失败三种状态。

约 30 分钟先修：02Java 21 · Boot 4.1
从你的前端经验出发

TypeScript 的类型主要在编译后消失；Java 的类同时参与运行时映射。record 很适合 API DTO，但不代表所有对象都深度不可变。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：独立 jshell 实验。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

record 是数据载体而非万能实体

record 自动提供构造器、访问器、equals、hashCode 和 toString，适合任务查询结果这类稳定数据。访问器名是 title()，不是 getTitle()。它的组件字段不可重新赋值，但如果组件指向可变 List，列表内容仍可能被修改；要得到更可靠的值对象，通常在构造时做防御性复制。

record 的简洁应服务业务表达。构造器可以维护不变量，如标题不能为空；它不是替代边界校验的理由。持久化实体通常有生命周期和框架映射要求，后面的 JPA 课程会使用普通类。不要为了少写代码把请求 DTO、数据库实体、响应对象强行变成同一个类型。

import java.util.*;
record TaskView(long id, String title, List<String> tags) {
  public TaskView {
    if (title == null || title.isBlank()) {
      throw new IllegalArgumentException("title is blank");
    }
    tags = List.copyOf(tags); // 复制集合，避免外部修改泄漏进来
  }
}
var tags = new ArrayList<String>();
tags.add("spring");
var view = new TaskView(1, "学习", tags);
tags.add("changed");
System.out.println(view.tags());

不存在和失败不是同一回事

Optional 表达“成功查询但可能没有结果”，例如按任务 ID 查找。数据库连接异常则表示查询没有正常完成，不应伪装成 Optional.empty。调用端可用 map 转换存在的值，用 orElseGet 延迟提供默认值，用 orElseThrow 把不存在转换为明确业务异常。直接 get() 又不检查存在性，会把本来清晰的分支变成运行时意外。

Optional 更适合作为返回类型，不必把每个实体字段和方法参数都包进去。默认值计算昂贵时，orElse 的参数在方法调用前已求值，即使结果存在也会执行；orElseGet 的供应函数才是按需调用。这样的求值差异在涉及数据库、日志或外部请求时尤其重要。

原始资料：Java 21 Optional API。

异常携带失败原因，不能吞掉

受检异常要求调用者捕获或继续声明；RuntimeException 不强制处理，但同样应该有明确语义。业务层可抛出 TaskNotFound 这类异常，HTTP 层再转成 404。不要在每层 catch Exception 后返回 null，这会让真正的错误更晚发生，并抹掉诊断线索。

本课在 jshell 中独立运行，不需要 Spring。把每一步结果先写下来再执行，强迫自己从引用、复制和控制流推导行为。结束时关掉代码，解释为什么 List.copyOf 保护的是集合结构，为什么列表元素若仍然可变就还需要额外处理；能够给出反例才说明你理解了边界。

Optional<String> title = Optional.of("学习");
System.out.println(title.map(String::length).orElse(0));
System.out.println(Optional.<String>empty().orElseGet(() -> "未命名"));
// /exit 退出 jshell

还应区分引用比较与内容比较。两个组件相同的record通常equals为true，但用双等号比较的是对象引用，不能表达业务值相等。把任务标题作为Map键时，字符串内容比较与正确的equals/hashCode共同影响查询结果；这也是理解值对象比只记语法更有用的原因。

原始资料：Java 21 Optional API。

Optional.empty 最适合表达什么？
查看判断依据

正确答案：查询正常但无值。不存在是成功结果的一种；基础设施失败应传播为错误，不能隐藏成空值。

把知识变成操作

在 jshell 中验证集合复制和 Optional。

  1. 运行 jshell，逐行粘贴 TaskView 示例。
  2. 追加 tags 后观察 view.tags()；尝试 view.tags().add("x")。
  3. 把 List.copyOf 删除后重新定义另一个 record，对比可变集合影响。
验收信号

复制版本只含 spring，修改其 tags 抛 UnsupportedOperationException；未复制版本受原列表修改影响。

做完再看：参考答案与排错线索

title.map(String::length).orElse(0) 得到 2；空 Optional 的默认值是“未命名”。record 的 final 只阻止组件引用被重新赋值，无法自动冻结组件引用指向的对象。
