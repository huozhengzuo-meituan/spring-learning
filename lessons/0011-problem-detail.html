Lesson 11 / 48 · 02 · HTTP 与可测试 API

用 ProblemDetail 表达错误

建立稳定错误合同，并保留服务器诊断能力。

约 30 分钟先修：10Java 21 · Boot 4.1
从你的前端经验出发

前端需要可判断的错误代码和字段信息，后端需要内部异常链；两者不应被混成一段堆栈文本。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：examples/hello-api。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

错误也是一种资源表示

Problem Details 用标准字段描述HTTP失败，Spring的 ProblemDetail 支持这种表示。status 是HTTP状态，title是简短类别说明，detail帮助解释这一次失败，type标识问题类型，instance可关联出错请求。还可以附加code或字段错误等扩展，但要稳定命名，不要让客户端依赖数据库错误原文。

一个任务不存在时，用户需要知道无法找到任务；运维需要根据日志定位查询路径。将SQL、服务器目录、堆栈和访问令牌全部塞进detail既不利于前端处理，也会泄漏实现信息。内部日志保留异常链和关联标识，外部响应提供能采取行动的描述；两个面向不同读者的输出都不可省略。

原始资料：Spring MVC Error Responses。

在 HTTP 边界集中映射

@RestControllerAdvice 可将业务异常映射为HTTP响应。让业务服务抛出 TaskMissing，而不是到处拼 ResponseEntity，可避免HTTP协议侵入业务层。下面是可参考的教学片段：状态码是404，稳定code是TASK_NOT_FOUND；实际项目已有错误处理时，先阅读其分类再扩展，不要创建互相竞争的处理器。

框架自身会产生参数解析、校验和不支持媒体类型等异常。要把这些错误也整合进合同，可以使用Framework提供的异常处理扩展，或启用Boot相关Problem Details能力并做针对性验证。处理器之间有顺序和匹配规则，所以不能只验证业务异常就宣称所有错误统一。

class TaskMissing extends RuntimeException {}

// 放在 @RestControllerAdvice 中的教学方法
@org.springframework.web.bind.annotation.ExceptionHandler(TaskMissing.class)
org.springframework.http.ProblemDetail missing(TaskMissing ex) {
  var problem = org.springframework.http.ProblemDetail.forStatusAndDetail(
      org.springframework.http.HttpStatus.NOT_FOUND, "任务不存在");
  problem.setTitle("Task not found");
  problem.setProperty("code", "TASK_NOT_FOUND");
  return problem;
}

原始资料：RFC 9457 Problem Details。

别用统一处理掩盖分类

catch Exception 然后全部返回400会把数据库宕机伪装成用户输错；全部返回500又会让客户端无法区分可修正输入和服务器故障。异常映射需要明确边界：输入错误、认证授权失败、不存在、并发冲突与基础设施失败分别处理。某些Security错误在MVC之前产生，不能期待ControllerAdvice天然覆盖整个过滤器链。

还要避免错误接口再次抛错。例如用Map.of构造错误字段时塞入null，会在处理原异常时再发生异常。处理代码应简单、少依赖外部服务。验证时查看真实HTTP状态、Content-Type、JSON结构和日志关联；只看到body里的status=404而状态行为200，并不是正确合同。

错误代码由接口所有者维护，给前端展示的文案可以随语言调整，但code不能跟着中文句子随意改变。HTTP请求中客户端自带的关联标识也不能完全信任，应限制长度与字符并避免日志注入；没有标识时由服务生成更合适。

查看判断依据

正确答案：服务端处理失败。连接失败不能证明资源不存在或用户输入错误，应保留服务端故障语义。

把知识变成操作

比较不存在、参数错误和未知路由的错误合同。

  1. 启动hello-api，查询一个未创建的合法UUID，例如00000000-0000-0000-0000-000000000000。
  2. 提交空白title，再请求不存在路由。
  3. 逐个记录HTTP状态、Content-Type、主要错误字段，比较一致与不同之处。
验收信号

不存在与校验失败能被区分；响应不泄漏堆栈、SQL或凭据。

做完再看：参考答案与排错线索

任务不存在应为404，字段校验为400。Spring安全过滤器产生的401/403需要Security层相应处理，不应通过扩大ControllerAdvice捕获范围来猜测修复。若未知路由结构不同，把它记录为待统一边界。
