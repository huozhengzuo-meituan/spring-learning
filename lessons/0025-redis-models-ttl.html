Lesson 25 / 48 · 05 · Redis 与缓存

Redis：从数据模型到 TTL

为任务详情、成员集合和排行榜选择结构，并亲眼验证过期行为。

约 30 分钟先修：关系型数据建模与SQL基础 / 基础设施集成验证Java 21 · Boot 4.1
从你的前端经验出发

前端 Map 很熟悉，但 Redis 是跨进程共享状态：每次访问有网络成本，所有实例都可能改同一个键。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：独立 Redis CLI；使用根 compose.yaml 的 redis 服务。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

先按访问方式建模

缓存详情可以用 String 存一个 JSON 快照；局部修改多个字段适合 Hash；唯一成员用 Set；按截止时间排序用 Sorted Set。选型先写“我要如何读写”，再选命令，不要因为关系数据库有一张表就照搬一个巨型 Hash。任务系统的键可以写成 course:task:v1:42：业务前缀防止冲突，版本前缀支持数据格式升级，标识符定位实体。键中不要包含密码或完整访问令牌。一个集合越大，完整读取它对网络、内存和事件循环的压力越大。

运行一次完整生命周期

在根目录启动 Compose 的 redis 服务，然后进入 CLI；下面只改 course 前缀的学习数据。EX 秒和 PX 毫秒很容易混淆，SET 时一起设过期避免两条命令中间崩溃。TTL 返回 -2 表示键不存在，-1 表示没有过期时间，正数是剩余秒数。缓存时效是业务约定，不是数据一致性证明。

docker compose up -d redis
docker compose exec redis redis-cli
SET course:task:v1:42 '{"title":"学习事务"}' EX 60
GET course:task:v1:42
TTL course:task:v1:42
HSET course:member:7 name Lin role writer
SADD course:team:3 7 8 7
SCARD course:team:3
ZADD course:due 1800000000 42 1800000300 43
ZRANGE course:due 0 -1 WITHSCORES

一个容易漏掉的覆盖规则

对有 TTL 的键再次执行普通 SET，会替换值并移除原 TTL；需要保留时用 KEEPTTL，需要刷新时重新指定 EX。Hash 中更新字段与替换整个键的行为不同，因此不要笼统记成“写操作都刷新 TTL”。读取后在客户端减 TTL 再写回也会制造并发窗口。键消失还可能来自淘汰、主动删除或服务重建；排查时要同时检查过期、内存策略和部署记录。Redis 保存的是缓存副本时，丢失应能从数据库重建。

把数据量当成设计输入

假设有十万条详情，每条一 KB，不能只把数值相乘当成所需内存：还有键、对象结构、连接缓冲、复制和持久化开销。先从真实样本测 MEMORY USAGE，再评估命中率和总量。遍历学习键用 SCAN；不要在生产大库直接 KEYS *。分页扫描期间数据可能改变，因此 SCAN 不是事务快照。任务详情、排行和权限可能要求不同的过期策略；权限校验不能依赖一份没有失效机制的陈旧缓存。

一手阅读：Redis 数据结构；EXPIRE 语义。带着本课实验的输出阅读；有任何不清楚的步骤，可以直接把命令和结果发给学习助手继续追问。

遇到WRONGTYPE时，先用TYPE检查键结构，不要为了让命令成功而直接删除业务键。串行执行两个网络请求通常比一次批量读取更慢，但批量也必须限制返回体大小。实验记录应把键名、类型、生命周期、重建来源放在同一张表，未来修改格式时才知道哪些消费者会受影响。

合上笔记，先判断

覆盖带 TTL 的键且仍需保留剩余寿命，应选择什么？
查看判断依据

正确答案：保留过期写入。使用 SET key value KEEPTTL；普通 SET 会清除原有过期设置，分步删除重写有并发窗口。

把知识变成操作

验证 SET 覆盖值对 TTL 的影响，并证明 Set 会去重。

  1. 执行 SET course:ttl a EX 60，再执行 TTL。
  2. 执行 SET course:ttl b，再执行 TTL；解释结果。
  3. 重新设 EX 60，使用 SET course:ttl c KEEPTTL；检查 TTL。
  4. 执行 SADD course:test:set x x y，再执行 SCARD。
验收信号

普通覆盖后 TTL 为 -1；KEEP TTL 后仍为正数；集合成员数为 2。

做完再看：参考答案与排错线索

TTL不是独立于键生命周期的永久属性。把过期与写值放在同一条命令；Set的唯一性由成员值决定。
