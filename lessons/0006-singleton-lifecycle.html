单例 Bean 与并发请求

发现共享可变字段造成的数据串扰，并理解初始化与销毁。

约 25 分钟先修：05Java 21 · Boot 4.1
从你的前端经验出发

浏览器里的组件实例常按页面创建；Spring 默认单例 Bean 通常由很多请求共享，不能把它当成每个用户一份的对象。

本课服务于同一个目标：独立交付并排查可靠的业务后端。实验入口：独立 jshell 实验；examples/hello-api。标注为教学片段或设计实验的代码需要按题目补入，不代表示例已实现该功能。

单例限定在容器和 Bean 定义内

Spring 默认 singleton 是某个容器中某个 Bean 定义的一份实例，不是整个世界只能有一个 Java 对象，也不代表不同应用实例共享内存。应用扩容为三个进程时，每个进程都有自己的服务 Bean。prototype 每次向容器取对象可创建新实例，但把它注入单例时，默认并不会在每个方法调用自动重新获取。

单例服务最容易出错的写法是把 currentUser、lastRequest、临时集合放到成员字段。请求甲刚赋值，请求乙就可能覆盖；甲的后续逻辑读取到乙的数据。方法内局部变量属于本次调用，而共享字段需要明确并发策略。final 只固定引用，不保证其指向对象的内部修改安全。

原始资料：Spring Bean Scopes。

原子操作不是一切业务规则的原子性

计数器 count++ 包含读取、加一、写回，并非一个不可分割动作。AtomicInteger 可保证单次增量原子，但它无法自动保护“读取余额、检查、扣减、写入”这样的跨步骤业务不变量。ConcurrentHashMap 也只保证其规定的操作语义，先 containsKey 再 put 仍是两个操作；要选用 putIfAbsent 或计算方法表达整体意图。

下面使用并行流制造共享访问，输出不安全计数可能偶尔碰巧正确，这不能证明安全。观察到一次丢失更新就足够证伪。生产业务计数若需要跨多个进程一致性，还必须放到数据库或其他共享系统，而不是给 JVM 字段加锁就结束。

import java.util.concurrent.atomic.*;
import java.util.stream.*;
var unsafe = new int[]{0};
IntStream.range(0, 100000).parallel().forEach(i -> unsafe[0]++);
System.out.println(unsafe[0]);
var safe = new AtomicInteger();
IntStream.range(0, 100000).parallel().forEach(i -> safe.incrementAndGet());
System.out.println(safe.get());

原始资料：Java AtomicInteger。

生命周期只做相应阶段的事

构造器用于建立对象有效状态；依赖组装后可以通过 Jakarta 的 @PostConstruct 完成轻量初始化，销毁时用 @PreDestroy 释放自己拥有的资源。不要把漫长远程调用或永久循环塞进初始化，这会让应用迟迟无法就绪。某些被容器管理的资源已经有关闭机制，重复关闭也会制造错误。

初始化阶段不能随意假设事务、缓存等代理调用已经按你想象工作；尤其自身方法调用不会自然经过外部代理。需要启动任务时选择明确的启动扩展点，并考虑失败如何反馈。练习结束后应能回答：这个对象谁拥有，哪些字段共享，失败时谁负责清理，扩容后哪些数据会分裂成多份。

原始资料：Java AtomicInteger。
